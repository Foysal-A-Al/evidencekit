# Audit repair release — v0.3.0

The 3 November audit identified nine defects or readiness gaps. This release addresses the software defects and completes bounded technical validation. It does not manufacture customer demand, a valuation, general superiority, full browser certification or comprehensive security.

| Audit item | Resolution and evidence |
|---|---|
| A1 release drift | Browser assets/tests are reconciled with the public source. Private Site configuration/credentials are excluded from public source. Release manifest records shared asset SHA-256 values. |
| A2 runtime workflow | Optional bounded runtime logs are redacted, correlated with source paths and classified as suspected syntax/dependency/logic/configuration/resource signals. Prompts carry logs and require authorized reproduction. A controlled AI-authored HTTP failure/repair demo records actual before/after checks. The browser never executes repository code. |
| A3 quota dependence | Explicit local-folder collection completes without GitHub network access; cached review uses the displayed revision and rejects a changed-target cache miss. Find problems refreshes GitHub. |
| A4 sensitive exports | Quoted/unquoted and prefixed credential assignments are excluded from source; runtime text redacts assignments, bearer/URL credentials and complete/truncated private-key blocks. Export review is explicit. Filtering remains best-effort. |
| A5 import identity | Schema 2 echoes a SHA-256 snapshot fingerprint derived from target/revision/scope and ordered file hashes. Mismatches reject; unbound legacy findings are BLOCKED. A fingerprint binds data, not author authenticity; imported claims remain suspected. |
| A6 rebuild | A reconstruction brief uses the bounded source independently of repair-warning selection, labels unexecuted source/unknown runtime behavior and requires evidence references. |
| A7 Clear/privacy | Inputs, cache, report/source DOM and manual-copy text are emptied. Generation guards stop a delayed clipboard failure from restoring cleared content. Clipboard/downloads already created by the user are outside app-owned state. |
| A8 validation | Five actual fixture failures and reference repairs pass; the ten pinned subscribed-model trials are complete. Both conditions pass 5/5, with no demonstrated guided advantage. MiroFish remains one fictional-persona interview, not customer evidence. |
| A9 response errors | Bounded reader cancellation, streamed timeouts and invalid JSON produce useful failure messages; no misleading private-repository assertion. |

Independent read-only review found delimiter/prefixed-key redaction gaps, delayed clipboard restoration, retained hidden DOM and changed-target cache fall-through. Reproductions were observed failing before fixes and passing afterward. The full source suite also passes; exact final counts are recorded in the delivery report.

## Remaining verification limits

Signed-in production browser flows require an authenticated browser session. Service-authorized production probes showed that static `_headers` declarations were not enforced. Hosting now serves the exact embedded assets through a small ESM Worker that applies CSP, nosniff, frame, referrer, permissions, cache and transport headers on every route; the fixed serving boundary has a focused regression test. The available cloud browser reached the private sign-in gate; managed HTTP preview lacks secure Web Crypto needed for collection. Browser layout was inspected, and UI event flows were tested in a DOM simulation; neither substitutes for full authenticated browser QA. Current Windows global skill invocation and exhaustive prompt-injection/security testing remain unverified. No payment integration or paid API was added. Real customer validation requires real developers and remains unproven.

## Budget and safety

No auth-store/.env values were read or published. MiroFish containers/volumes were preserved. No arbitrary third-party project code was executed. Reference verifiers and comparison repairs run only owned isolated fixtures. No repeated MiroFish interviews were generated merely to inflate validation volume.
